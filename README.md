# Google TV RTK. Language files ZIP((XML)-XLSX-ZIP(XML) convertor

Fully client-side HTML converter for Android translation archives.

- ZIP archive with `values*/*.xml` resources → consolidated XLSX
- choose one, several, or all languages before creating the XLSX; base `values` is always included
- consolidated XLSX → ZIP while preserving the source archive hierarchy
- visible workbook layout matches the supplied `All translations` reference
- XLSX → ZIP validates every mapped XML resource and rewrites only XML files with real value changes
- exact hidden resource mapping prevents collisions between equal IDs in different XML files or resource types
- optional corrections from multiple language-specific workbooks
- optional capitalization alignment: when English starts with a capital letter, each available translation does too
- corrected XLSX can be downloaded before rebuilding the ZIP
- source and output ZIP archives can be compared row-by-row with an XLSX differences report and correction-file verification
- generated files automatically become the default inputs for the next workflow step
- files never leave the browser

Open `dist/index.html` through a local web server, or use the published GitHub Pages URL.

For a legacy XLSX that was not generated by this converter, select its original ZIP as the reference when rebuilding. Generated workbooks carry a very-hidden round-trip payload and do not need a separate reference ZIP.

The reverse converter parses the workbook and validates every mapped XML resource on each run. Unchanged XML is not serialized again. When the workbook contains no value changes, the embedded source ZIP is returned byte-for-byte after validation. Generated results are not restored from a browser cache: every click performs the selected conversion again.

Generated workbooks contain a very-hidden resource map that identifies the exact XML path and resource type for every visible row. The visible `All translations` structure remains unchanged. A legacy workbook without that map is accepted only when its `App` / `string ID` / `item ID` mapping is unambiguous; otherwise the converter asks for a newly generated XLSX instead of modifying several unrelated XML resources.

## Correction workbook

Download the template from the application or create a separate XLSX for each language. Its first sheet must contain these columns:

| App | string ID | item ID | values | values-xx (original) | values-xx (corrected) |
| --- | --- | --- | --- | --- | --- |
| application name | resource identifier | array item or blank | English reference | complete current translation | complete corrected translation |

Replace `xx` in both language columns with the target qualifier, for example `values-cs (original)` and `values-cs (corrected)`. Corrections are matched by `App`, `string ID`, and `item ID`, and the current translation must exactly match the original value. Correction files accumulate across repeated file-picker selections, remain visible with their detected languages, and can be removed individually or cleared together. The earlier `Language`, `Old text`, `New text` layout remains supported for compatibility.

After selecting a ZIP, the converter scans its `values*` folders and displays a searchable language list. All languages are selected by default. Use **All**, **Clear**, or individual checkboxes to control which language columns are included in the consolidated workbook.

## ZIP comparison report

Select a source ZIP and an output ZIP. The application parses supported Android `string` and `string-array` translation rows and creates an XLSX workbook with:

- `Summary`: overall counts plus matching, difference, correction-verification, conflict, and capitalization statistics for every language;
- `Differences`: changed, missing, added, and correction-audit rows with language, exact XML path, resource type, source/output values, and conclusion.

The `Differences` sheet includes a `Conclusion` column and four audit columns for every corrected language: correction source workbook/row, original correction value, expected corrected value, and verification result. Successful correction targets are included even when the source and output ZIP values already match. The first row has Excel filters across every report column.

The ZIP selected in step 01 and the ZIP generated in step 02 are used automatically when the comparison upload fields are empty. Likewise, the XLSX generated in step 01 becomes the default correction input, and a corrected XLSX becomes the default input for ZIP conversion.

Comparison is based on parsed translation values rather than ZIP compression or binary file bytes.
